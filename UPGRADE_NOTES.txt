MeeCreeps Fork - post-compile gameplay/UI fixes

This revision fixes the following issues found during in-game testing:
- Safe portal-origin placement is now checked independently from destination placement.
- Horizontal portal origin placement is supported by the same safe-placement logic as vertical portals.
- The destination search treats custom Y as a reference and searches nearby safe surfaces.
- The Destination Wheel no longer draws LEFT/CENTER/RIGHT labels.
- Wheel hover highlighting is drawn over the current-destination highlight so the cursor location is visually authoritative.
- Hover/selection state is reset every frame instead of persisting from an earlier mouse position.
- Custom destinations remain runtime-only and never write into saved destination NBT.
- Selecting/saving a normal destination clears any temporary custom/Fast Return override.
- Auto-Close-disabled portals keep a visible renderer scale and stay open until explicitly closed.
- Manual closing works for Auto-Close-disabled portals as well.
- Horizontal portal trigger volumes were widened so players can actually enter them.
- Portal target Y placement no longer pushes horizontal arrivals downward.
- Self-pair portal creation is rejected safely.


Gameplay correction pass 2:
- Restored the original source/origin portal placement path; custom destination Y never influences the source portal.
- Custom Y is used only as a reference for the exit portal safe-location search.
- Saved destinations use exact saved coordinates and orientation; they are not forced through the custom safe-search algorithm.
- Saved wall/floor/ceiling orientations now validate their actual support face, fixing horizontal destination failures without moving the saved destination.
- Custom destination search preserves a requested direction whenever possible and records the actual fallback direction when another safe orientation is required.
- Bidirectional portal anti-loop protection now blocks an entity only while it remains inside the destination portal trigger volume, allowing intentional return travel after the player leaves the portal.
- Restored the original thin horizontal trigger planes, fixing accidental cross-side triggers and improving wall-portal behavior.
- Restored the original portal arrival Y baseline.
- J now closes portals from the active Portal Gun while the Destination Wheel GUI is open.
- Invalid/unavailable saved destinations can no longer be selected server-side; custom dimensions are rejected before selection/portal creation.
- Saved-destination display remains client-compatible while server-side selection performs authoritative dimension availability checks.

Final stabilization pass:
- Bidirectional teleport loops are prevented with a short entity cooldown plus a destination-portal exit latch, so entering a portal cannot immediately bounce the player back even when the two portal orientations differ.
- Custom Y-reference search now scans the full buildable height near the requested X/Z, so high/low approximate Y values find the same nearby ground surface instead of requiring an exact Y.
- Registered but unloaded dimensions are initialized before destination validation; their destination chunks are loaded before any safety test.
- Open portal chunks are force-loaded while the portal exists and the chunk ticket is released when the portal closes.
- J is now a global in-game keyboard action while holding the Portal Gun, and no longer depends on the wheel GUI.
- J closes portals with the normal closing animation rather than deleting them immediately.
- Portal opening animation is independent of Auto-Close, so disabling Auto-Close no longer makes newly created portals pop in instantly.
- Original saved-destination obstruction/error behavior is retained instead of being replaced by the custom safe-search error.
- PacketSetDestination and Portal Gun destination checks now initialize registered dimensions rather than falsely reporting a valid unloaded dimension as invalid.
- Custom direction parsing accepts lower-case direction letters as a convenience while retaining the documented U/D/W/E/N/S syntax.
